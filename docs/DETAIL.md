# 鲫鱼（dsh-fish-jiyu）· 线性投影压缩

给 DeepSeek Harness 的**无损回取**压缩引擎：按距离把待压历史投成三档，近的保原文、中间的提纯、远的只剩关键词和 seq 指针，原文全部留在会话日志里，需要时按指针取回。

## 为什么做这个

vcc 会把历史压成「检查点正文」，而检查点自己又进下一轮上下文——每压一次，链就长一截。鹦鹉螺（dsh-fish-fold）把每块折成一行叙事摘要，压得更狠，但摘要记不住，而且仍然是一条越来越长的链。

鲫鱼换了个做法：**不叠链，每次从原始日志重新投影一遍**。

## 怎么工作

自带引擎与编译器：`lib/engine/`（触发、事务、区间选择、surface 协议）与 `lib/compiler/`（条目渲染、词元、噪声、检查点）都在本包内，所以**不需要另装 vcc**。宿主内核只提供四个包：`@deepseek-ai/dsh-compaction`、`dsh-llm`、`dsh-util-values`、`schemastery`，那是本体自带的（`lib/host.js` 是唯一的适配入口）。

内核最初搬自 dsh-compaction-vcc（MIT，2026-11-27 起由本包接管维护，`lib/vcc/` 已删除）：触发与事务通道沿用它的做法，条目渲染则由 `lib/compiler/` 按放宽的尺度自己编（每段正文 2048/4096 token），所以近段拿到的是接近原话的行。来源、偏离与许可约定见 [`vcc-fork.md`](vcc-fork.md)。

预算是挂在**触发线**上的，不是挂在检查点上限上：上限的一半比触发线还高，压完人还在触发线上头，会一压再压。现在取「上限 × `thresholdRatio` × 0.5」做目标，再用「实际可用体积的 85%」压一层——压完落回线下，也不会超过 vcc 的产物体积。然后从最近几块开始往里加原文，加到预算为止，剩下的按距离退档：

| 档 | 内容 | 例子 |
| --- | --- | --- |
| 近段 | 原文逐条保留；块数不写死，预算有余就多保一段（「近的尽量保全」） | 完整对话 |
| 中段 | 每块一行事实：时间、你的原话、动过什么工具、收尾、`seq` 区间 | `[块 seq 3323-3325 · 23:16] 「…」 · 收尾「…」 · 原文按 seq 取回` |
| 远段 | 每块只剩关键词 + `seq` 区间；另有一条全局「词 → 区间」索引 | `[块 seq 9-44] 词：风扇 bug 修复 扇设定数` |

取回：自带三个只读工具——`jiyu_search(关键词)` 在原文里搜出 `seq`，`jiyu_recall(seq 区间)` 分页读回原话，`jiyu_blocks()` 列出每块的档位与区间。底层读的是当前会话的事件日志（`session.snapshotEvents()`），一个字都没删。

工具结果单独处理：原文不进上下文（整段是百万 token 级），只抽一行摘要——有报错行就取报错行，否则取末行。中段每块的事实行会带上最多两句「结果」；近段里失败的工具行补一句结果，成功的靠正文自己说。其余按 seq 取回。

旧检查点条目一律折成一行指针（`[块 seq N] 更早的检查点…`），所以上下文里不会出现「摘要的摘要」——这一步通常还能顺手省下几万 token。

## 能做什么 / 不能做什么

能：

- 把长历史压到窗口的一个预算内，同时保住最近那段的原文；
- 让远处历史仍然可检索：关键词行和索引都带 `seq` 区间，能落回日志取原文；
- 长会话里每轮压缩的结果是「投影」而不是「续写摘要」，总量有上限、不会滚雪球；
- 同一块的行一旦进过窗口就不再重写：第二次投影逐字节沿用（`frozen`），前缀缓存不因重投影失效；
- 中段事实行按 KEEP 清单留碎片：路径（带盘符或绝对路径）、精确报错、带单位的数值、带理由的决策，「留「…」」里的内容优先保全。

不能：

- 不能凭空恢复上下文窗口：压得再聪明也只是延迟爆窗；
- 中段事实行是规则抽取，不是模型改写，它只负责导航，不复述细节；
- 短寒暄（「可爱捏」这种）本身没什么可检索的词，远段会退化成一两个词，不保证取回；
- 中文没有分词器，关键词是 2–4 字 n-gram，偶尔出现「具箱 / 救者」这种半截词，检索够用，读着难看。

## 配置

沿用 vcc 的配置面（写在 `cordis.patch.yml` 的 `compaction-jiyu` 段）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `thresholdRatio` | 0.35（包自带 bundle 与 `DEFAULT_THRESHOLD` 一致） | 上下文压力到窗口多少比例时触发压缩 |
| `retainTurns` | 1 | 保留最近几轮原文 |
| `retainTokens` | 16384 | 保留区 token 上限 |

投影本身的常数在 `index.js` 顶部：`DEFAULT_THRESHOLD`（读不到 `thresholdRatio` 时的兜底，0.35）、`TARGET_SHARE`（目标取触发线的几成，0.5）、`SHRINK_KEEP`（相对上游产物至少压掉一成五）、`NEAR_TEXT_TOKENS` / `NEAR_USER_TOKENS`（近段逐条渲染的放宽尺度，2048/4096）、`DEFAULT_NEAR_BLOCKS`、`DEFAULT_MID_MAX`、`DEFAULT_FAR_WORDS`。

## 冻结与 KEEP（2026-11-18）

这两条是读过 billion-context 的设计后加的，对应它论文里「只压增量、前缀永不失效」和「摘要工艺 KEEP/DROP」两节。

**冻结。** 投影时会先扫一遍输入条目里已有的块行（`[块 seq a-b …]` 这种），按起始 seq 建索引；生成中段/远段时，同一块如果已经有行、且区间对得上，就直接沿用那一行的原文，不重新生成。理由是缓存：窗口前缀是逐字节比对的，同一块每轮重新措辞，整段前缀就作废，服务端要整窗重算。测试里有一条「同一块重投影后逐字节不变」，21 块 0 块被改写。

边界：块边界变了（新消息改变了切块）才会重新生成；旧检查点被折成指针行那一步不参与冻结，因为指针文本只由 seq 决定，本身稳定。

**KEEP。** 中段事实行除了标题、工具、结果，还会从收尾和你的原话里按优先级抓最多两条碎片：Windows 路径 → Unix 路径 → 精确报错串（`error`/`failed`/`exception`）→ 带单位的数值（`3558 rpm`、`12 ms`、`%`）→ 带理由的决策（「因为/所以/原因是/避免」）。抓到什么就写进「留「…」」。取舍是：这些碎片丢了就得整段翻回去，占几个字很划算；其余细节仍由「原文按 seq 取回」兜底。

## 相关性提档（2026-11-18）

原来的分档只看时间远近：越近越细，越远越粗。问题是它不知道你正在干什么——翻一份很早的材料办事，那份材料照样被折成关键词行，只剩一个 seq。

现在加了一层：拿最近几块（保原文的那几块）的关键词当「当前话题」，远处的块如果和这些词重合到两个以上，就从关键词行升到事实行。重合一个不算，免得满屏都是「相关」的。

它不调模型、不算向量：`blockKeywords` 已有的中文 n-gram 直接拿来比对，零额外开销。代价是只认字面——换个说法就认不出来，真正的语义相关性还是得靠 embedding，等有模型再换这一层。

测试：`test/relevance.mjs` 四条（无话题退回关键词档、中两个词提档、只中一个不提、近段不受影响）。`tierOf` 多了第五个参数 `queryWords`，不传就是老行为。

## 决策报告：jiyu_inspect（2026-11-18）

参考 dsh-context 那套上下文洞察之后加的，但只做压缩侧那半——它看的是「上下文由什么组成」，这里看的是「引擎为什么这么切」。

每次投影成功，引擎把报告写到 `$DSH_HOME/fish-jiyu/last-report.json`：遮蔽区间、上限、目标、压前压后、每块落在哪一档（原文 / 事实行 / 关键词）以及**为什么**落在那一档（离得最近 / 动过工具 / 和当前话题沾边 / 按时间距离）。最后一次写的是数组，保留最近十次，能看前后差别。

`jiyu_inspect` 三种用法：不给参数看最新一次；`index` 看往前第几次；`list` 列出最近几次的压前压后与压缩比。

只读、不触发压缩、不改任何东西。报告写不出也不影响压缩（整个 writeReport 包在 try 里）。

学 dsh-context（bowenliang123）的分工：算的归宿主，看的归前端。

**界面还在包里，但注册不生效（2026-11-21 记）**：做过一版浮层和会话头入口，客户端模块始终注册不上去，界面上从没出现过。2026-11-20 删过一次，后来退版退到删除之前，`client.js`、`view.js`、`inspect.html` 又回来了，`package.json` 的 `exports`／`files`／`dsh.client` 和 `cordis.patch.yml` 的 `jiyu-view` 也都还挂着。

**为什么不删**：删干净要同时动三处（三个文件、清单三段、配置两行），少一处就是配置指向不存在的模块，下次加载直接报错。加载器那一层至今没读透，2026-11-20 就是在这里栽的。所以现在选了加注释：三个文件顶部都写了「死代码，别照它改」，行为和以前一样——跑不到，不显示，也不报错。

要看压缩情况用 `jiyu_inspect` 工具，同一份数据一条命令。

**新增 seq 范围（2026-11-21）**：报告多了 `seqFrom` / `seqTo`，是这次压缩盖住的 seq 区间。有它，记忆体那头才能说清「上次压掉的是哪一段」，光有压前压后说不清。

**按会话分开存（2026-11-18 改）**：以前所有会话写同一份 `last-report.json`，切到别的会话看到的还是上一条的压缩记录。现在报告按会话落到 `$DSH_HOME/fish-jiyu/reports/<会话>.json`，各留最近十次；同时更新一份全局 `last-report.json` 给 `jiyu_inspect` 兜底（它不知道会话时读那份）。

## 边界与已知限制

- 引擎内核源自 dsh-compaction-vcc（MIT），现由本包接管：`lib/engine/` 与 `lib/compiler/`；宿主接口集中在 `lib/host.js`，宿主换版只改这一处。
- 与 vcc、fold、basic 四选一：同一个 `ctx.compaction` 只能有一个实现。本包的 bundle patch 会关掉 `compaction-fold` 与 `compaction-basic`；旧 profile 里若还开着 `compaction-vcc`，`install.sh` / `install.ps1` 会顺手关掉它。
- 只在本机（DSH 2.36 + vcc 0.7.4）验证过；换机器、换模型窗口不受影响，但阈值要按窗口比例配。
- 中段事实行由规则抽取，不做模型改写：它负责导航，不负责复述；要细节就按 seq 取原文。
- 短寒暄没有可检索的词，远段不保证能取回；重要的小事请让它落到文件或记忆页里。

## 与肥鱼记忆体配合

记忆体的约束存活核对挂的是宿主 `session/event` 里的 `compaction/summary`，读 `data.summary` 与 `data.shadowedSeqs`。投影式压缩的远段只剩关键词，整句比对会误报「压丢」，所以配合方式放在记忆体那一侧：它先找覆盖约束 seq 的那一行投影，按那行的关键词覆盖核（`keywordCoverage`），找不到行才退回整句比对。

引擎这边**不为记忆体做特殊处理**：分档只看距离和「有没有动过工具」，约束词不提档。

## 原文取回：jiyu_search / jiyu_recall / jiyu_blocks（2026-11-22）

以前这里写着「取回：`recall(seq)` 或 `search(关键词)`」，但那两个工具在宿主里并不存在——原文确实没删，可能不能取回全看有没有人手动解压日志。这一版把承诺补成了工具。

**三个工具，全部只读。**

| 工具 | 做什么 | 边界 |
| --- | --- | --- |
| `jiyu_search(query, limit, all)` | 按词在事件正文里搜（用户话、助手话、工具调用与结果都算），返回 `seq` + 摘录，标注「已折叠 / 在窗口内」 | 字面匹配，不做同义词；`all: true` 时连没被折叠的也搜 |
| `jiyu_recall(from, to, offset, maxChars)` | 按 `seq` 区间读回原文，默认 6000 字一页，页尾给下一个 `offset` | 只读，不改 surface；分页是为了不撞工具结果截断 |
| `jiyu_blocks(tier, limit)` | 读最近一次压缩报告，列块：档位、`seq` 区间、分档理由 | 只读报告，没有报告就说没有 |

**为什么不做成「按块 decompress」。** 块只是压缩时的一个分组，日志里没有块边界；按 `seq` 区间取回是同一件事，而且不依赖引擎记住块号——重启后报告在、块号就在，报告没了也还能按搜索到的 `seq` 取。

**和投影的关系：没有关系。** 新工具不参与压缩决策、不改阈值、不注册压缩后端，只在被调用时读一次日志。压缩该压还是压，远段该只剩关键词还是只剩关键词。

**模块化。** 删掉 `lib/recall.js`、`tool.js` 里 `registerRecallTools` 那一行 import 和调用，工具就没了；引擎那半不受影响。

**测试。** `node --test test/recall.mjs`：正文抽取（含工具调用）、区间取回、分页 offset、块 → 折叠集合。实测（2026-11-22）：`jiyu_search("阈值")` 命中 5 条，`jiyu_recall(3550, 3550)` 读回「把他的压缩阈值改到0.35，根据压缩之后再给我结果」。
