# 0.4.15（2026-11-25）

## 撤销：不再把 tool-result-pruner 设成 2000/1200/500

0.4.13 起，安装时会把宿主的剪裁阈值从默认 8192 调到 2000，依据是「工具结果进上下文前会剪中间段，省约 15%」。

**这个依据是错的。** 读 `dsh-compaction-basic` 源码后确认：`pruneSession` 只在**压缩判定**时被调用一次，不是每轮都剪。实测当前窗口 266 条工具结果里只有 14 条超 2000，剪完省 11.3% 字符。

代价却一直在：超过 2000 字符的输出，中间段当场被换成剪裁标记——读一个大文件，后半段就没了。

所以 0.4.15 起：

- `install.sh` 改为调用 `scripts/clear-tool-pruner.mjs`，**只撤销**我们当年写的三项，回到宿主默认 8192；
- `uninstall.sh` 也会做同样的撤销，卸载后不留残留配置；
- 不再主动设置任何阈值。别人的自定义值不会被碰。

## 升级方式

和以前一样：`bash install.sh`。装完重启宿主生效。
