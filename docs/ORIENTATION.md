# 设计取向（不是功能说明）

> 改代码前先读这一页。职责边界看 `scope.md`，改动记录看 `docs/CHANGES-*.md`。
> 这一页只回答三个问题：**它是什么、它故意不做什么、什么情况下该推翻现在的做法。**

---

## 1. 它是什么

**压缩的基底，不是平台。**

只做一件事：上下文接近上限时，把它投成三档——近段原文、中段一行事实、远段关键词 + seq 指针；压掉的原文能按 seq 取回。

它的价值不在“压得多”，在**压完还能对回去**。

---

## 2. 它故意不做什么

| 不做 | 为什么 |
|---|---|
| 调模型写摘要 | 零模型调用是硬约束：不花钱、不连网、同样输入同样输出；模型摘要会编、会丢、会变 |
| 语义/向量检索 | 两页事实相反时它分不开；词面至少认“不”字 |
| 自动把旧内容注回上下文 | 自动注错比不注更糟；要查就显式查 |
| 智能判断“哪条要求还生效” | 只抽显式祈使句，宁可漏；抽错等于给我一条假规则 |
| 记忆、人格、主动性、任务调度 | 那些是别的插件的事，本包不碰 |
| 改旧检查点 | 已写入的块行逐字节冻结，改了就破前缀缓存 |

---

## 3. 关键取舍

| 取舍 | 选择 | 代价 |
|---|---|---|
| 确定性 vs 智能 | 纯规则投影 | 抽不出隐含要求，理解不了换说法 |
| 准确 vs 完整 | 中段每块只留一行，工具结果只摘 48 字 | 关键细节在中间时看不见，得 recall |
| 省空间 vs 可读 | 远段只剩关键词 | 旧事只能靠索引和 seq 找 |
| 缓存稳定 vs 及时更新 | 块行冻结、约束区逐字节继承 | 旧内容不会自动修正 |

---

## 4. 四个不变量（改代码不能碰）

1. **每块都有落脚点**：预算再紧，每个块的 seq 至少出现在一行里；
2. **冻结行逐字节不变**：同一块重投影必须完全一致；
3. **报告字段是接口**：`at/before/after/seqFrom/seqTo/summary/blocks` 改语义算破坏性变更；
4. **失败不连累压缩**：投影出错就退回上一版结果，不抛给宿主。

---

## 5. 什么情况下该推翻

| 信号 | 说明 |
|---|---|
| 词面取回率长期低于 60% | 才谈换检索方式 |
| 压缩后重复劳动明显上升 | 说明摘要/事实行留错了东西 |
| 窗口大到压缩不再必要 | 就删掉这层，不要养着 |
| 宿主提供官方压缩接口且够用 | 优先接官方，不维护分叉 |

---

## 6. 改之前问自己

1. 会不会破上面四个不变量中的任何一个？
2. 压缩后还比原文小吗（加内容必须先算账）？
3. 旧会话还能正常投影吗（不要求新数据才支持）？
4. 有没有测试钉住这次改的行为？
5. 失败路径会不会静默？（今天踩过：漏 import 只在调用时炸）
