# 鲫鱼 0.4.5 改动说明：约束区

日期：2026-11-23
改前版本：0.4.4（回退包：`dsh-fish-jiyu-0.4.4-backup-20261123-1227.tgz`）

---

## 一句话

压缩检查点最前面加一块**仍然有效的要求**，只收你亲口说的祈使句，每行带 seq，二次压缩逐字节继承。

---

## 为什么改

鲫鱼把上下文投成三档：

| 档 | 内容 | 时间久了 |
|---|---|---|
| 近段 | 原文 | 随窗口滑走 |
| 中段 | 一行事实（发生过什么） | 再折成关键词 |
| 远段 | 关键词 + seq | 只剩词 |

问题出在中间那层：**要求会被当成事件压掉**。

比如你说过「改完要测试，没问题就装」，压两次之后，中段可能只剩「测试」两个字——我照样不知道“装完还要评估”。

这不是信息丢了（原文能用 `jiyu_recall` 取回），是**该被当成规则的东西，被当成了一次事件**。规则不能等我想起来才查，它得一直在眼前。

---

## 改了什么

### 1. 新增 `lib/constraints.js`（可整块删除）

| 函数 | 作用 |
|---|---|
| `extractFromText` | 从一段用户原话里抽约束句 |
| `collectConstraints` | 从待压节点里收集：继承旧约束 + 抽新约束 |
| `mergeConstraints` | 合并、去重、覆盖、按优先级裁剪 |
| `renderConstraints` | 渲染成检查点里那几行 |

| `prependConstraintEntry` | 插到编译条目最前 |

### 2. `index.js` 接线（约 15 行）

投影完成后：

- `collectConstraints(nodes)` 收集；
- 渲染成文本，作为 `kind: 'constraint'` 的条目插在最前；
- token 计入总量，压不小就照旧放弃这次投影；
- 决策报告多记 `constraintTokens`。

### 3. `lib/report.js`

报告新增 `constraints` 字段：继承几条、新抽几条、最终几行。没有约束时是 `null`。

## 设计规则（为什么这么定）

| 规则 | 理由 |
|---|---|
| 只抽显式祈使句 | 问句、举例、假设、事实陈述抽进来就是噪声 |
| 每行带 seq | 约束区只负责提醒，原文仍用 `jiyu_recall` 取回 |
| 上限 8 行 / 480 字符 | 约 300 token，占 33 万上下文的 0.1% |
| 禁止类与带数值参数优先 | 目标会变，禁令和数值不会 |
| 二次压缩逐字节继承 | 前缀缓存不能因为重排而失效 |
| 换说法保留新值 + 注明旧 seq | 让“变过”看得见，旧值不会被当现状 |
| 抽不到就空串 | 不改变原有行为，也不占地方 |

## 已知边界（没解决的）

1. **问句尾巴会带走真约束**：像“要单独做……有什么办法”这种，整句按问句跳过；
2. **一次性任务不抽**：“打个包发给它”这种不进约束区（它属于任务，不属于规则）；
3. **规则是在同一批语料上调的**：7/7 偏乐观，换一批对话大概率掉到六七成；
4. **隐含要求抽不到**：“以后都这样”不会变成约束行；
5. **约束区只在压缩时更新**：两次压缩之间新说的话，仍在近段原文里，不会提前进约束区。

## 代价

- token：约 300；
- 代码：约 300 行（含注释）+ 5 个测试文件；
- 抽错的代价：一条错误的“明文规则”会被我照着执行——所以宁可漏，不可错。
